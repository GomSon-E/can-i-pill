# 이거뭐약 화면 설계서
> 약 + 영양제 + 음식 상호작용 리스크 탐지 AI 에이전트
> 타겟: 50~60대 여성 | 로컬 저장 | 메인 컬러: 마젠타 핑크 계열
> 📌 설계 노트: 이 앱은 로그인 및 회원가입 기능이 없습니다. 관련 UI 요소를 포함하지 마세요.

# 1. 앱 소개 플로우 (워크스루)

---

## SS-INTRO-01 | 워크스루 1 — 공감
> 앱 소개 (1/3)

**화면 설명**
앱을 처음 실행한 사용자가 보는 첫 화면. "이런 경험 있으신가요?"로 시작해 타겟 사용자의 페인포인트에 즉시 공감을 유도한다.

**이전 / 다음**: 앱 최초 실행 → SS-INTRO-02

### 구성 요소

| 항목 | 내용 |
|------|------|
| 배경 | 따뜻한 플랫 일러스트 — 어머니와 자녀가 영양제를 함께 보는 장면|
| 메인 문구 | 이런 경험 있으신가요? |
| 예시 상황 | "자녀가 보내준 홍삼, 내 혈압약이랑 같이 먹어도 될까?" / "당뇨약 먹는데 이 영양제 괜찮은 건지..." / "약사한테 물어보기엔 너무 작은 것 같고..." |
| 하단 네비게이션 | 점(dot) 인디케이터 3개 + 다음 버튼 → SS-INTRO-02 / 건너뛰기 → SS-OB-02 |

### UX 고려사항
- 첫 화면에서 설명하지 말고 공감 먼저 — 50~60대는 긴 설명보다 내 얘기에 반응
- 말풍선 문구는 실제 어르신이 쓸 법한 자연스러운 말투로
- 건너뛰기 버튼 제공 — 이미 아는 사용자 배려
- 좌우 스와이프로도 이동 가능

> 앱 소개 (2/3)

**화면 설명**
이거뭐약이 무엇을 해주는지 핵심 기능을 3가지로 간결하게 설명하는 화면.

**이전 / 다음**: SS-INTRO-01 ← → SS-INTRO-03

### 구성 요소

- 전문 용어 절대 금지 — "RAG", "VLM", "Agent" 노출 금지
- 아이콘 + 짧은 문장 조합 — 이미지로 먼저 이해하도록
- 카드 애니메이션: 위에서 아래로 순차 페이드인 (250ms, 과하지 않게)

## SS-OB-01 | 기본정보 입력
> 온보딩 (1/5)

**화면 설명**
앱 시작 시 사용자의 기본 정보를 입력하는 첫 온보딩 화면. 닉네임·생년월일·성별을 입력해 개인화된 경험을 제공한다. 입력 항목을 최소화해 진입 장벽을 낮춘다.

**이전 / 다음**: 앱 시작 → SS-OB-02

### 구성 요소

| 항목 | 내용 |
|------|------|
| 진행 표시 | 프로그레스 바 (1/5 단계 표시) |
| 닉네임 입력 | 어떻게 불러드릴까요? (입력 필드) / 예시: 김영희, 어머니, 엄마 / 최대 10자 |
| 생년월일 입력 | 생년월일을 알려주세요 (연도·월·일 선택 휠 또는 숫자 입력) / 연령대 기반 맞춤 안내에 활용 |
| 성별 선택 | 여성 / 남성 (선택 버튼 2개) / 선택 안 함 옵션 포함 |
| 다음 버튼 | 다음 (주 CTA, 하단 고정, 전체 너비) |
| 건너뛰기 | 나중에 입력하기 (텍스트 버튼) |

### UX 고려사항
- 닉네임은 앱 전체에서 "○○님, 오늘도 건강하세요" 형태로 사용
- 생년월일 입력은 키보드 대신 선택 휠 사용 — 숫자 입력 오류 방지
- 성별은 의사·약사 Agent 소견 개인화에 활용 (여성 호르몬 관련 약 등)
- 모든 항목 건너뛰기 가능 — 강제 입력 없음
- 하단 안내 문구: "입력한 정보는 기기에만 저장돼요. 나중에 설정에서 언제든 바꿀 수 있어요"

### 데이터 흐름
- **Input**: 없음
- **Output**: 닉네임·생년월일·성별 로컬 저장

## SS-OB-02 | 건강정보 등록
> 온보딩 (2/5)

**화면 설명**
지병 및 알레르기 정보를 선택형 UI로 등록하는 첫 온보딩 화면. 강제 입력이 아니라 건너뛰기를 허용해 진입 장벽을 낮춘다.

**이전 / 다음**: SS-INTRO-03 ← → SS-OB-03

### 구성 요소

| 항목 | 내용 |
|------|------|
| 진행 표시 | 프로그레스 바 |
| 지병 선택 | 다중 선택 가능 / 선택 시 강조 표시 / 📌 설계 노트: SS-OB-01 생년월일·성별 기반으로 연령대·성별에 맞는 지병 10개를 동적 노출. 단, 이 사실을 화면에 표시하지 않습니다 |
| 지병 Top 10 (50~60대 여성) | 고혈압, 당뇨, 고지혈증, 골다공증, 갑상선질환, 관절염, 위장질환, 심장질환, 빈혈, 우울·불안 |
| 지병 Top 10 (50~60대 남성) | 고혈압, 당뇨, 고지혈증, 통풍, 심장질환, 위장질환, 전립선질환, 간질환, 호흡기질환, 수면장애 |
| 기타 | "여기 없어요" 버튼 → 직접 입력 필드 노출 / 여러 개 추가 가능 (+ 추가 버튼) / 각 항목 개별 수정·삭제 가능 |
| 알레르기 | 알레르기 있음 토글 → ON 시 알레르기 버튼 그리드 노출 |
| 건너뛰기 | 지금은 건너뛰기 |
| 다음 버튼 | 다음 |

### UX 고려사항
- 텍스트 직접 입력 없이 선택형으로만 구성
- SS-OB-01 건너뛴 경우 (나이·성별 미입력) → 전체 공통 지병 10개 기본값으로 노출
- SS-OB-01 건너뛰기 버튼 최소 44×
- 선택 상태 마젠타 핑크 강조 — 선택됐는지 명확히 표시
- 건너뛰기 허용 — 강제 입력 시 이탈률 증가
- 기타 선택 시 텍스트 입력 필드 1개만 노출

### 데이터 흐름
- **Input**: 없음
- **Output**: 지병·알레르기 정보 로컬 저장 → 사용자 DB 초기화

## SS-OB-03 | 처방전 촬영 및 등록 ★ 핵심
> 온보딩 (3/5)

**화면 설명**
처방전을 사진으로 찍어 약물 DB를 생성하는 핵심 온보딩 화면. OCR/VLM이 처방전에서 약물 목록을 자동 추출한다.

**이전 / 다음**: SS-OB-02 ← → SS-OB-04

### 구성 요소

| 항목 | 내용 |
|------|------|
| 진행 표시 | 프로그레스 바 |
| 안내 문구 | 병원에서 받은 처방전을 찍어주세요 / 처방전이 잘 보이게 평평하게 놓고 찍으면 돼요 |
| 예시 이미지 | 올바른 처방전 촬영 예시 카드 |
| 촬영 버튼 | 처방전 사진 찍기 |
| 갤러리 선택 | 갤러리에서 선택하기 |
| 건너뛰기 | 나중에 등록하기 |

- 인식 실패 시 "다시 찍기" + "직접 입력하기" 대안 제공
- 처리 중 로딩 화면에서 취소 버튼 제공

### 데이터 흐름
- **Input**: 처방전 이미지
- **Output**: OCR/VLM 약물 목록 추출 → SS-OB-04로 이동

## SS-OB-04 | 약물 추출 결과 확인 (용도 매칭) ★ 개선
> 온보딩 (4/5)

**화면 설명**
OCR/VLM이 추출한 약물을 건강정보 기반으로 용도(당뇨약·혈압약 등)와 자동 매칭하는 화면. 어르신이 성분명 대신 익숙한 용도명으로 확인·저장하도록 한다.

**이전 / 다음**: SS-OB-03 ← → SS-OB-05

### 구성 요소

| 항목 | 내용 |
|------|------|
| 진행 표시 | 프로그레스 바 |
| 안내 문구 | 처방전에서 찾은 약이에요. 각 약이 무슨 약인지 확인해주세요 |
| 약물 카드 구조 | **당뇨약 💊** (크고 굵게) ← 용도명 / 메트포르민 500mg (작게) ← 성분명 / [당뇨약] [혈압약] [고지혈증약] [기타] 칩 버튼 / [삭제 X] |
| 약물 분류 로직 | **① 지병 연관 약**: SS-OB-02 선택 지병 + 성분 DB 교차 → 용도명 자동 매칭 (당뇨약·혈압약 등) |
| | **② 보조 약물**: 지병과 무관한 약 → 쉬운 말로 자동 변환 (위장보호약·염증약·수면보조제·비타민 등) |
| | **③ 매칭 불가**: "어떤 약인가요?" 칩 버튼으로 직접 선택 유도 |
| 보조 약물 변환 예시 | 오메프라졸 → 위장보호약 / 이부프로펜 → 염증약·진통제 / 트리아졸람 → 수면보조제 / 비타민C → 비타민 / 마그네슘 → 미네랄 보조제 |
| 보조 약물 색상 구분 | 이모지 색상으로 약 종류 구분 (🟡 위장보호·수면 계열 / 🟠 염증·진통 계열 등) — 지병 약(💊)과 시각적으로 구분 |
| 화면 구성 | 지병 약 섹션 (상단) + 보조 약물 섹션 (하단) 으로 구분 표시 |
| 약 표기 방식 | 앱 전체 "당뇨약 (메트포르민)" 형태로 병기 |
| 추가 버튼 | + 약 직접 추가하기 |
| 확인 버튼 | 이게 맞아요, 시작하기 |
| 재촬영 | 처방전 다시 찍기 |

### UX 고려사항
- 용도명 우선, 성분명 보조 표시
- 자동 매칭 틀렸을 때 칩 버튼으로 1탭에 수정 가능
- 보조 약물(위장보호약·염증약 등)은 별도 섹션으로 구분해 표시 — 지병 약과 혼동 방지
- 보조 약물 변환이 틀렸을 때 칩 버튼으로 수정 가능
- 처방전 이름 자동 제안 시 대표 약(용도명)이 2개 이상이면 가장 많은 약의 용도명으로 제안
- 이름 미입력 시 "처방전 1", "처방전 2" 순번으로 자동 저장
- 완료 시 "총 N개 약이 등록되었어요" 토스트

### 데이터 흐름
- **Input**: OCR 추출 약물 리스트 + 건강정보 + 약물 성분-용도 매핑 DB
- **Output**: 용도 태그 포함 약물 로컬 DB 생성 완료 → SS-MAIN-01

## SS-OB-05 | 영양제 등록
> 온보딩 (5/5)

**화면 설명**
현재 복용 중인 영양제를 미리 등록하는 마지막 온보딩 화면. 라벨 촬영 또는 제품명 검색으로 등록한다. 영양제가 없으면 건너뛰기 가능하며 나중에 언제든지 추가할 수 있다.

**이전 / 다음**: SS-OB-04 ← → SS-MAIN-01

### 구성 요소

| 항목 | 내용 |
|------|------|
| 진행 표시 | 프로그레스 바 (5/5 단계 표시) |
| 안내 문구 | 지금 드시는 영양제가 있으신가요? (크고 굵게) / 미리 등록해두면 나중에 물어볼 때 더 편해요 (보조 텍스트) |
| 라벨 촬영 버튼 | 영양제 라벨 사진 찍기 (주 CTA, 카메라 아이콘) → SS-MAIN-03 촬영 UI 재사용 |
| 제품명 검색 | 제품명으로 찾기 (검색 입력 필드) → 식약처 건강기능식품 DB 자동 매칭 |
| 등록된 영양제 리스트 | 등록 완료된 영양제 카드 리스트 / 제품명 (크게) + 주요 성분 (작게) / 삭제(X) 버튼 / 개수 제한 없음 |
| 추가 등록 | + 영양제 추가하기 (리스트 하단 버튼) — 라벨 촬영 or 제품명 검색으로 계속 추가 가능 |

| "아니요" 선택 시 | 해당 약 카드 취소선 + 배경 / 처방전 새로 찍기 or 이 약만 삭제하기 |
| 하단 버튼 | 모두 그대로예요 / 변경된 약이 있어요 / 나중에 확인할게요 |
| 딤 배경 | 뒤로가기로 닫기 불가 |

### UX 고려사항
- 용도명 우선 표시
- 전체 "네" 시 "건강하게 잘 챙겨드시고 있네요! 👍" 토스트
- 팝업 배경 딤 처리 — 버튼으로만 닫기

### 데이터 흐름
- **Input**: 로컬 약물 DB + 마지막 확인일 타임스탬프
- **Output**: 약물 DB 업데이트 + 마지막 확인일 갱신
